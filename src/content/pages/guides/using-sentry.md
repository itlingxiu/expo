# 使用 Sentry

[Sentry](https://getsentry.com/) 是一个崩溃报告平台，提供"生产部署的实时洞察，以及复现与修复崩溃所需的信息"。它会提醒你用户遇到的异常/错误，并把它们组织到 Web 仪表盘中。报告自动包含堆栈跟踪、设备信息、版本与其他上下文；你还可以添加应用特定的上下文，例如当前路由与用户 ID。

## 你将学到

本指南涵盖三件事：在 React Native 应用中安装与配置 Sentry；将 Sentry 与 EAS 一起使用 —— [EAS Build](/guides/using-sentry#usage-with-eas-build) 用于构建，[EAS Update](/guides/using-sentry#usage-with-eas-update) 用于 OTA 更新；以及[设置 Sentry-Expo 集成](/guides/using-sentry#sentry-integration-with-eas-dashboard)，在 EAS 仪表盘中查看崩溃报告与 Session Replay。

## 安装并配置 Sentry

### 注册 Sentry 账户并创建项目

你必须先有一个 Sentry 账户与项目。

**1.1** [注册 Sentry](https://sentry.io/signup/)（免费额度每月最多 5,000 个事件），并在仪表盘中创建项目。记录三个值：

- **organization slug** —— 位于 **Organization settings** 标签页
- **项目名称** —— 位于项目的 **Settings > Projects** 标签页（从列表中选择）
- **DSN** —— 位于 **Settings > Projects > 项目名称 > SDK Setup > Client Keys (DSN)** 标签页

**1.2** 在 [Developer Settings > Auth Tokens](https://sentry.io/settings/auth-tokens/) 页面，创建一个新的 [Organization Auth Token](https://docs.sentry.io/account/auth-tokens/#organization-auth-tokens)。它会自动获得 Source Map Upload 与 Release Creation 的权限范围；请保存好。

拿到 organization slug、项目名称、DSN 与 auth token 后，就可以继续了。

### 使用 Sentry 向导设置项目

推荐且最简单的方式是 Sentry 向导，它会自动配置正确的设置。在项目目录中运行：

```sh
# npm
npx @sentry/wizard@latest -i reactNative

# yarn
yarn dlx @sentry/wizard@latest -i reactNative

# pnpm
pnpm dlx @sentry/wizard@latest -i reactNative

# bun
bunx @sentry/wizard@latest -i reactNative
```

向导会：

- 安装必需的依赖
- 配置你的项目以使用 Sentry
- 自动设置 Metro 配置
- 向应用添加初始化代码

按照提示操作；向导会帮助你登录 Sentry 并获取正确的项目信息。

### 验证配置

创建一个新的 release 构建，确认 source map 上传正确。要测试一切正常、sourcemap 已接好，可以添加一个按钮：

```jsx
import { Button } from 'react-native';

// Inside some component
<Button title="Press me" onPress={() => { throw new Error('Hello, again, Sentry!'); }}/>
```

## 与 EAS Build 一起使用

在构建环境中以[敏感可见性](https://docs.expo.dev/eas/environment-variables.md#visibility-settings-for-environment-variables)设置 `SENTRY_AUTH_TOKEN`。Sentry 随后会自动上传 source map。如果你依赖环境变量而不是应用配置中的属性，也一并设置。完成这些步骤后，EAS Build 无需额外工作。

## 与 EAS Update 一起使用

运行 `eas update` 后，把 source map 上传到 Sentry：

```sh
# npm
# Pass in the "dist" directory generated by `eas update` to the upload script
npx sentry-expo-upload-sourcemaps dist

# yarn
# Pass in the "dist" directory generated by `eas update` to the upload script
yarn dlx sentry-expo-upload-sourcemaps dist

# pnpm
# Pass in the "dist" directory generated by `eas update` to the upload script
pnpm dlx sentry-expo-upload-sourcemaps dist

# bun
# Pass in the "dist" directory generated by `eas update` to the upload script
bunx sentry-expo-upload-sourcemaps dist
```

你的更新中的错误随后会在 Sentry 中正确符号化（symbolicate）。

#### 想在一条命令中发布更新与 sourcemap？

用 `&&` 串联命令，一步完成发布与上传：

```sh
eas update --branch <branch> && npx sentry-expo-upload-sourcemaps dist
```

#### 想给错误报告附加更多与更新相关的元数据？

用更新信息标记 Sentry scope，就能在 Sentry 仪表盘中看到与特定更新关联的错误。在应用生命周期的尽早阶段，把这段代码加入全局 scope：

```js
import * as Sentry from '@sentry/react-native';
import * as Updates from 'expo-updates';

const manifest = Updates.manifest;
const metadata = 'metadata' in manifest ? manifest.metadata : undefined;
const extra = 'extra' in manifest ? manifest.extra : undefined;
const updateGroup = metadata && 'updateGroup' in metadata ? metadata.updateGroup : undefined;

Sentry.init({
  // dsn, release, dist, etc...
});

const scope = Sentry.getGlobalScope();

scope.setTag('expo-update-id', Updates.updateId);
scope.setTag('expo-is-embedded-update', Updates.isEmbeddedLaunch);

if (typeof updateGroup === 'string') {
  scope.setTag('expo-update-group-id', updateGroup);

  const owner = extra?.expoClient?.owner ?? '[account]';
  const slug = extra?.expoClient?.slug ?? '[project]';
  scope.setTag(
    'expo-update-debug-url',
    `https://expo.dev/accounts/${owner}/projects/${slug}/updates/${updateGroup}`
  );
} else if (Updates.isEmbeddedLaunch) {
  // This will be `true` if the update is the one embedded in the build, and not one downloaded from the updates server.
  scope.setTag('expo-update-debug-url', 'not applicable for embedded updates');
}
```

之后，关联更新的详情会出现在错误标签区域中。（图片：Sentry 更新标签）

## 与 EAS 仪表盘的 Sentry 集成

此集成让你直接在 EAS 仪表盘中查看 Expo 部署的崩溃报告与 Session Replay，链接到 Sentry 的完整上下文堆栈跟踪、session 回放与调试工具。

### 安装

> 安装此集成需要 Sentry 的 owner、manager 或 admin 权限。

1. 登录你的 Expo 账户，打开 [**Account settings > Overview**](https://expo.dev/accounts/%5Byour-account%5D/settings)。
2. 在 **Connections** 下，点击 Sentry 旁边的 **Connect**。
3. 登录 Sentry 并接受集成进入你的组织；你会被重定向回 **Account settings**。

### 关联你的项目

连接账户后，把 EAS 项目关联到 Sentry 项目：

1. 在 EAS 中打开 **Projects > [你的项目] > Configuration > Project settings**。
2. 点击 **Link**，从下拉列表中选择你的 Sentry 项目。

### 用法

通过 **Projects > [你的项目] > Updates > Deployments > [Deployment]**（针对某个 Release）查看 Sentry 数据。有了此集成，你可以：

- 直接在 EAS 仪表盘中查看崩溃报告
- 访问 Session Replay，了解错误发生前发生了什么
- 获取带完整上下文的详细堆栈跟踪
- 在 EAS 与 Sentry 之间跳转以进行调试
