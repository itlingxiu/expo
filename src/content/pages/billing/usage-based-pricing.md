# 按用量计费

Expo 对超出[套餐](/billing/plans)限额的付费套餐客户按用量计费。这让客户可以使用所需的用量，而不必担心限额或合同义务。

按用量计费对 EAS Build 和 EAS Update 启用，并按月结算。我们会在[账户的 Billing](https://expo.dev/settings/billing)上提供现有用量和任何超额费用的估算。

## 按用量计费如何工作

### EAS Build

对于 EAS Build，以更高优先级执行的单次构建会收取固定费用。这按月汇总，并在计费周期结束时收费；如果提前取消套餐，则会更早收费。

:::note
在任何工作开始之前取消的构建不会收费。
:::

[Starter、Production、Enterprise 和 Legacy 套餐](/billing/plans#套餐)的订阅者会获得 EAS Build 额度。这些额度可以用来抵消构建费用。它们在计费周期开始时重置，并在该计费周期结束时过期。受支持构建平台的价格表和可用资源类见我们的[定价页面](https://expo.dev/pricing)。

#### 示例：EAS Build 额度用量（Production 套餐）

假设一个订阅了 Production 套餐的账户，在一个计费周期内有 15 次 medium Android 构建和 10 次 large iOS 构建：

| 说明 | 价格 | 数量 | 合计 |
| --- | ---: | ---: | ---: |
| Android 构建（medium） | $1 | 15 | $15 |
| iOS 构建（large） | $4 | 10 | $40 |
| EAS Build 额度 | | | -$55 |
| **合计（USD）** | | | **$0** |

由于额度包含在 Production 套餐中，订阅者为其 25 次构建支付 $0。

#### 示例：超出 EAS Build 额度（Production 套餐）

再看一个超出额度上限的例子：

| 说明 | 价格 | 数量 | 合计 |
| --- | ---: | ---: | ---: |
| Android 构建（medium） | $1 | 20 | $20 |
| Android 构建（large） | $2 | 10 | $20 |
| iOS 构建（medium） | $2 | 30 | $60 |
| iOS 构建（large） | $4 | 40 | $160 |
| EAS Build 额度 | | | -$225 |
| **合计（USD）** | | | **$35** |

在这种情况下，订阅者为 100 次构建支付 $35，而不是 $260，因为 EAS Build 额度覆盖了 $225。

### EAS Update

:::tip
使用[定价计算器](https://expo.dev/pricing#update)估算你的 EAS Update 用量。
:::

EAS Update 的按用量计费包含两个指标：月活跃用户和全球边缘带宽。

“已更新用户”反映在一个计费周期内至少下载一次更新的唯一用户数量，也称为“月活跃用户”（MAU）。全球边缘带宽表示超出订阅套餐基础带宽配额的带宽总量。如果月活跃用户超过套餐的基础 MAU 配额，每位额外用户包含 40 MiB 全球边缘带宽。

:::note
无论该用户下载多少次更新，一个月活跃用户在每个计费周期只计一次。在 EAS Update 的语境中，“用户”指应用在一台设备上的一次唯一安装。
:::

每个套餐都把一定数量的月活跃用户和全球边缘带宽包含在订阅中。各套餐的数量不同。最新数字见我们的[定价页面](https://expo.dev/pricing)。

#### 示例：EAS Update 用量（Starter 套餐）

假设一位 Starter 套餐订阅者通过 EAS Update 向 10,000 名用户部署了 20 次更新，每次 5 MiB。该套餐订阅包含 3,000 个月活跃用户和每月 100 GiB。因此，订阅者额外用量的账单将是：

| 说明 | 价格 | 数量 | 合计 |
| --- | --- | --- | ---: |
| 已更新用户 | 每用户 $0.005 | 7,000 | $35 |
| 全球边缘带宽 | 每 GiB $0.10 | 603.13 GiB | $60.31 |
| **合计（USD）** | | | **$95.31** |

在 10,000 名用户中，3,000 名包含在 Starter 套餐中。因此，7,000 名按按用量计费收费。为 7,000 名已更新用户付费还包含约 273.4 GiB（7000 名用户 × 40 MiB / 1024）。

全球边缘带宽的计算是：

| 说明 | 计算 | 数量 |
| --- | --- | --- |
| 发送更新所用带宽 | 20 次更新 × 5 MiB × 10,000 名用户 | 976.5625 GiB |
| | | |
| 套餐包含的带宽 | | 100 GiB |
| 7,000 名额外已更新用户包含的带宽 | 7,000 × 40 MiB | 273.4375 GiB |
| **合计** | **976.5625 - 100 - 273.4375** | **603.125 GiB** |

如果同一位订阅者在当前计费周期内向同样的 10,000 名用户发送第 21 次 5 MiB 的更新，他们只需为额外使用的带宽付费。

| 说明 | 计算 | 数量 |
| --- | --- | --- |
| 发送更新所用带宽 | 21 次更新 × 5 MiB × 10,000 名用户 | 1,025.39 GiB |
| | | |
| 套餐包含的带宽 | | 100 GiB |
| 7,000 名额外已更新用户包含的带宽 | 7,000 × 40 MiB | 273.4375 GiB |
| **合计** | **1,025.39 - 100 - 273.4375** | **651.95 GiB** |

这是因为 Expo 只对[唯一月活跃用户](/eas-update/introduction#每月活跃用户是如何计数的)收费。因此，订阅者额外用量的账单将是：

| 说明 | 价格 | 数量 | 合计 |
| --- | --- | --- | ---: |
| 已更新用户 | 每用户 $0.005 | 7,000 | $35 |
| 全球边缘带宽 | 每 GiB $0.10 | 651.95 GiB | $65.2 |
| **合计（USD）** | | | **$100.2** |

如果同一位订阅者使用的是 Production 套餐，他们将支付 $0，因为 Production 套餐包含 50,000 个月活跃用户和 1 TiB（1024 GiB）。因此没有额外带宽用量。

## 监控用量

:::note
显示的账单估算最多可能延迟 24 小时（一天）。
:::

要查看当前计费周期的用量摘要，前往 [Billing > **Usage**](https://expo.dev/settings/billing)。你会看到 EAS Build、EAS Update 和其他服务的用量摘要。

![EAS 仪表板中 EAS Build、EAS Update 和 EAS Workflows 的账单用量摘要。](/static/images/billing/usage-01.png)

### EAS Build 用量历史

要查看当前或以往计费周期的详细 EAS Build 用量：

- 在导航菜单中点击 **Usage**。
- 在 **EAS Build** 部分，你会看到按平台和资源类划分的构建次数和已执行构建的详情。

![EAS 仪表板中的详细 EAS Build 用量。](/static/images/billing/usage-02.png)

### EAS Update 用量历史

要查看当前或以往计费周期的详细 EAS Update 用量：

- 在导航菜单中点击 **Usage**。
- 在 **EAS Update** 部分，你会看到已更新用户和全球边缘带宽的详情。

![EAS 仪表板中的详细 EAS Update 用量。](/static/images/billing/usage-03.png)

### 用量通知

当账户达到套餐所含 EAS Build 额度的 **80%** 和 **100%** 时，Expo 会向账户的 [Owner 和 Admin](/accounts/account-types#管理访问权限) 发送电子邮件通知。这帮助你在超额费用发生之前提前知晓。

这些通知默认启用。你可以在 [EAS 仪表板](https://expo.dev/settings/billing) 的 **Email notifications** 页面管理通知偏好。

![EAS 仪表板中的电子邮件通知偏好。](/static/images/billing/usage-04.webp)

### 如何优化构建用量

你可以使用 [EAS Update](/eas-update/introduction) 和[开发构建](/develop/development-builds/introduction) 来测试并部署新代码，而不必创建全新的构建。这会帮助你更快迭代并减少构建用量。

对大多数应用来说，JavaScript 代码的变化比底层原生代码和配置更频繁。如果每次代码变更都创建新构建，请考虑[使用 EAS Update 来利用 JavaScript 与原生代码不同的迭代频率](/eas-update/how-it-works)。这样你可以把这些变更作为更新发布。

使用持续集成（CI）/持续部署（CD）构建预生产代码时，可以自动化“只在原生代码发生变化时才构建”的过程，以减少不必要的用量。你可以在 CI/CD 中用 [Expo Fingerprint](https://expo.dev/blog/fingerprint-your-native-runtime) 创建工作流，检测原生代码是否变化，只有变化时才执行构建。否则，如果原生代码没有变化，就发布一次更新。

开发构建可以运行任何与其原生运行时兼容的 EAS Update。如果把 EAS Update 与多个测试渠道一起使用，可以让测试者或测试设备使用同一个开发构建，从而减少创建额外构建的需要。

### 如何优化更新用量

使用 EAS Update 时，你可以管理要包含或排除的某些资源。这会减少从更新服务器上传或下载的资源数量，以及所使用的全球边缘带宽。

要优化存储和带宽用量，可以选择排除未修改的资源。例如，没有变化的图片或视频可以排除。被排除的资源不会上传到更新服务器，也不会被应用下载。不过，重要的是确保不属于某次更新的资源已经包含在应用的原生构建中。

:::note
如果应用已经下载了同时也属于新更新的资源，应用不会重新下载该资源。这也不会增加账户的带宽用量。
:::

你可以用 `npx expo-updates assets:verify <dir>` 检查更新中是否包含所有必需资源。更多信息见[资源选择与排除](/eas-update/asset-selection)。
