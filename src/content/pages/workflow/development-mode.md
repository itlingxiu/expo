# 开发模式与生产模式

项目始终会以**开发**或**生产**模式之一运行。默认情况下，用 `npx expo start` 在本地运行项目会进入开发模式，而已发布的项目（使用 `eas update`）或任何独立应用则会以生产模式运行。

**开发模式**包含有用的警告，并让你可以使用让开发和调试更容易的工具。**生产模式**会[压缩代码](/guides/customizing-metro#压缩)，并且更能代表应用在终端用户设备上的性能。下面分别查看这两种模式，并了解如何在它们之间切换。

## 开发模式

React Native 包含一些非常有用的开发工具：在 Chrome 中进行远程 JavaScript 调试、实时重载、热重载，以及类似于你在 Chrome 中使用的检查器的元素检查器。若要了解如何使用这些工具，参见[调试](/debugging/runtime-issues)。

开发模式还会在应用运行时进行校验并给出警告。例如，你使用了已弃用的属性，或忘记向组件传入必需属性。下方视频展示了元素检查器与性能监视器在 Android 模拟器和 iOS 模拟器上的实际效果（`dev-prod/dev-mode.mp4`）。

:::warning
**这是有代价的。应用在开发模式下运行更慢。** 你可以用 Expo CLI 开关它，参见[生产模式](#生产模式)。切换后，关闭并重新打开应用，更改才会生效。**任何时候测试应用性能，都要确保关闭开发模式**。
:::

### 查看开发者菜单

该菜单提供一系列让开发和调试容易得多的功能。关于如何在 Android 和 iOS 上打开它，参见[开发者菜单](/debugging/tools#开发者菜单)。

## 生产模式

生产模式主要用于两件事：

- 测试应用性能，因为开发模式会明显拖慢应用。
- 捕捉只在生产环境出现的 bug。

模拟项目在终端用户设备上如何运行，最简单的方式是使用以下命令：

:::tabs
:::tab npm
```sh
$ npx expo start --no-dev --minify
```
:::
:::tab yarn
```sh
$ yarn expo start --no-dev --minify
```
:::
:::tab pnpm
```sh
$ pnpm expo start --no-dev --minify
```
:::
:::tab bun
```sh
$ bun expo start --no-dev --minify
```
:::
:::

它会以生产模式运行应用的 JavaScript（这会让 Metro 打包器把 `__DEV__` 环境变量设为 `false`，以及其他几件事）。`--minify` 标志会压缩应用。该标志还会去掉注释、格式化和未使用代码等不必要的数据。如果你的独立应用出现错误或崩溃，用此命令运行项目可以节省大量查找根因的时间。

:::note
在生产模式下，控制台日志不会出现在 Expo CLI 终端中。要通过设备上的原生日志访问它们，参见[在生产模式中查看控制台日志](/workflow/logging#在生产模式中查看控制台日志)。
:::

要为生产环境完整编译应用，参见[编译 Android](/more/expo-cli#编译-android)和[编译 iOS](/more/expo-cli#编译-ios)。
