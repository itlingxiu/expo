# Expo SDK 参考

> 本页面对应 Expo SDK v55。

:::note
您正在查找的页面在此 SDK 版本中不存在。它可能已被弃用，或在更新的 SDK 版本中新增。
:::

Expo SDK 是一组包的集合，提供对设备与系统功能的访问，例如相机、联系人、位置、传感器、触觉反馈等。每个包针对一个特定功能，可以独立使用。安装了 `expo` 包后，所有包都可以在任何 React Native 应用中使用。

您可以使用 [`npx expo install`](/more/expo-cli#install) 命令安装任何 Expo SDK 包。例如，以下命令同时安装了三个不同的包：

```sh
$ npx expo install expo-camera expo-contacts expo-sensors
```

安装一个或多个包后，您就可以在 JavaScript 代码中导入它们：

```js
import { CameraView } from 'expo-camera';
import * as Contacts from 'expo-contacts';
import { Gyroscope } from 'expo-sensors';
```

这样您就可以调用 [`Contacts.getContactsAsync()`](/versions/v55.0.0/sdk/contacts#contactsgetcontactsasynccontactquery) 从设备读取联系人、读取陀螺仪传感器检测设备运动，或者启动手机相机拍照。

## 所有 Expo SDK 包都可用于任何 React Native 应用

Expo 应用就是 React Native 应用，因此安装了 `expo` 包并完成配置后，所有 Expo SDK 包都可以在任何 React Native 应用中使用。创建支持 Expo SDK 包的 React Native 应用最简单的方法是使用 `create-expo-app`。不过，您也可以使用 `npx install-expo-modules` 命令为现有的 React Native 应用添加 Expo SDK 支持。

```sh
# 创建名为 my-app 的项目
$ npx create-expo-app my-app --template bare-minimum
```

- [在现有 React Native 应用中安装 Expo SDK 包](/bare/installing-expo-modules)：了解如何将使用 `npx @react-native-community/cli@latest init` 创建的项目配置为支持 Expo SDK 包。
- [使用第三方库](/workflow/using-libraries)：了解如何在项目中安装 Expo SDK 包。

## 使用预发布版本

新的 Expo SDK 版本每年发布三次。在这些发布之间，我们会发布 `expo` 包以及所有 Expo SDK 包的预发布版本。预发布版本不被视为稳定版本，只有在您能够接受遇到 bug 或其他问题的风险时才应使用。

### Canary 版本

Canary 版本代表发布时 `main` 分支状态的快照。Canary 包版本在名称中包含 `-canary`，以及日期和提交哈希，例如 `55.0.0-canary-20260121-a63c0dd`。要安装最新的 canary 版本：

```sh
# 安装 expo 的 alpha 版本及其相关包
$ npm install expo@canary && npx expo install --fix
```

您通常可以将单个包的预发布版本与 Expo SDK 的稳定版本一起使用。canary 质量的版本偶尔可能会出现不兼容或其他问题。如果您选择使用 canary 包，并且已经验证它在您的使用场景下工作良好，可以考虑[关闭依赖校验警告](/more/expo-cli#configuring-dependency-validation)。

### Beta 版本

在每次 Expo SDK 发布之前，我们都会发布 `expo` 包和所有 Expo SDK 包的 beta 版本。Beta 版本被认为比 canary 版本稳定得多，我们鼓励开发者在自己的应用上试用并提供反馈。Beta 版本在 npm 上使用 `beta` 标签，并遵循相关 [changelog](https://expo.dev/changelog) 文章中的说明。

## 每个 Expo SDK 版本都依赖一个 React Native 版本

> 本页面此处包含 React Native 版本兼容性表格，展示各 Expo SDK 版本与 React Native 版本的对应关系。

### 补充信息

<details><summary>Expo SDK 跟进 React Native 版本的政策</summary>

- Expo SDK 版本每年发布三次，每个 Expo SDK 版本针对一个特定的 React Native 版本。这通常是发布时最新的稳定版本。
- React Native 的发布节奏在其历史上有所变化，目前预计 2025 年将发布六次。在这种节奏下，可以预期每两个 React Native 版本就会有一个对应的 Expo SDK 版本。
- 即将发布的 Expo SDK 的预发布版本会快速包含对最新 React Native 版本的支持，通常在其发布的当天。每次 React Native 发布时，Expo SDK 团队都有一名成员参与 React Native 发布团队的工作，负责持续更新 Expo 仓库中的 React Native 版本、验证兼容性，并向 Meta 的团队报告回归问题。

</details>

<details><summary>为什么不立即为每个 React Native 版本发布新的 Expo SDK 版本？</summary>

在 Expo，我们发现每年发布三个大版本能够在稳定性和创新之间取得良好平衡，让依赖我们开源工具的开发者受益。Expo 与 Meta 在版本发布上紧密合作，我们会不断改进流程，让您尽快用上最新的 Expo 和 React Native 功能。

</details>

<details><summary>如果我需要最新 React Native 版本中的某个改动，但它还没有包含在 Expo SDK 版本中，该怎么办？</summary>

我们与 Meta 的团队紧密合作，确保所有紧急修复都会包含在最新 Expo SDK 所使用的 React Native 版本中。如果您的问题因为比较小众或涉及破坏性更改而不会被 cherry-pick 到现有版本中，那么您有两个选择：

1. 使用 [`patch-package`](https://github.com/ds300/patch-package) 引入该修复。
2. 使用 [Expo SDK 的预发布版本](#使用预发布版本)。这里有一个[示例](https://expo.dev/changelog/react-native-78)。

</details>

<details><summary>我可以在最新的 Expo SDK 中使用旧版本的 React Native 吗？</summary>

Expo SDK 中的包旨在支持该 SDK 所针对的 React Native 版本。通常情况下它们不支持旧版本的 React Native，但也可能支持。当新的 React Native 版本发布时，最新版本的 Expo SDK 包通常会更新以支持它。不过，根据发布中更改的规模，这可能需要数周或更长时间。

</details>

## Android 和 iOS 版本支持

每个 Expo SDK 版本都支持 Android 和 iOS 的最低操作系统版本。对于 Android，会定义 `compileSdkVersion`，它告诉 [Gradle](https://developer.android.com/studio/build) 使用哪个 Android SDK 版本编译应用。这也意味着您可以使用该 SDK 版本及之前版本中包含的 Android API 功能。对于 iOS，[Xcode](https://developer.apple.com/news/upcoming-requirements/) 指定了编译应用所需的最低 Xcode SDK 版本。

> 本页面此处包含 Android 与 iOS 版本兼容性表格，展示各 Expo SDK 版本支持的最低 Android/iOS 系统版本、`compileSdkVersion` 与 Xcode 版本要求。

在决定是否升级 Expo SDK 版本时，请同时考虑 Expo 的 SDK 版本和应用商店的提交要求，如上表所述。Google Play Store 和 Apple App Store 会定期提高新应用提交所要求的最低操作系统版本和 API 级别。Expo 无法控制应用商店的要求，您应查看 [Google](https://developer.android.com/studio/build) 和 [Apple](https://developer.apple.com/news/upcoming-requirements/) 了解当前的商店提交要求。
