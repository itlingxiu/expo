# 灰度发布

灰度发布让你先把一项变更推给一部分用户，以便在向全部用户发布之前发现 bug 或其他问题。

EAS 根据使用场景提供**按更新和按分支的灰度机制**。

## 按更新灰度

这种灰度机制让你在发布新更新时指定应接收它的用户百分比，之后再逐步提高该百分比。

### 开始

要开始基于更新的灰度，在普通的 `eas update` 命令上添加 `--rollout-percentage` 标志：

```sh
$ eas update --rollout-percentage=10
```

在此示例中，发布后该更新只对 10% 的终端用户可用。

### 推进

要修改基于更新的灰度百分比：

```sh
$ eas update:edit
```

系统会引导你选择要编辑的更新，并询问新的百分比。

### 结束

结束基于更新的灰度时，有两种选择：

- **完全推出**：按上文推进灰度，并把百分比设为 100。
- **恢复到先前状态**：运行 `eas update:revert-update-rollout`，它会引导你恢复到先前状态。

### 补充说明

- 同一时间一个分支上只能灰度一个更新。
- 灰度进行中时，必须先用上述选项之一结束灰度，才能发布新的更新（相同运行时版本）。这可以防止意外覆盖正在进行的灰度。
- 要查看灰度状态，使用 `eas update:list` 或 `eas update:view` 命令。
- 在已有更新的分支上回滚灰度，会重新发布对照更新。这确保所有客户端都恢复到先前状态。
- 可以在当前没有更新的分支上开始灰度，此时第一个更新会按指定百分比推给用户。回滚时会创建一个回滚到嵌入式更新的更新，从而把客户端恢复到先前状态（嵌入式更新）。

## 按分支灰度

这种灰度机制让你把新分支上的一组更新增量推给一定百分比的终端用户，其余用户仍留在当前分支。

### 开始

要开始基于分支的灰度，运行以下 EAS CLI 命令：

```sh
$ eas channel:rollout
```

终端中的交互式向导会协助你选择 channel、选择用于灰度的分支，并设置灰度用户百分比。要提高或降低灰度比例，再次运行该命令并选择 `Edit` 选项来调整百分比。

### 结束

在交互式向导中选择 `End` 选项时，有两种结束灰度的方法：

- **重新发布并恢复：** 当你对新分支的状态有信心时使用此选项。它会把新分支上的最新更新重新发布到旧分支，并且所有用户都会指向旧分支。
- **恢复：** 选择忽略新分支上的更新，并把用户送回旧分支。

### 补充说明

- 同一时间一个 channel 上只能灰度一个分支。
- 要查看灰度状态，使用 `eas channel:rollout` 命令。
- 灰度进行中时，你可以通过运行 `eas update --branch [branch]` 等方式，向正在灰度和当前的分支发布更新。
- 灰度进行中时不能使用 `eas update --channel [channel]`，因为它无法知道应把更新关联到灰度中的哪个分支。
